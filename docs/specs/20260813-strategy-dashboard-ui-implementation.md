# 전략 대시보드 HTML 초안 구현 — 2026-08-13

## 목적

`docs/specs/20260812-strategy-dashboard-v1.md`의 병렬 실험 계약을 유지하면서,
앞서 정한 dark charcoal + off-white floating card 초안을 실제 전략 화면의
의사결정 흐름으로 구현한다.

## 이번 구현 범위

- 기존 `검색·조회` 화면과 전략 화면의 2메뉴 구조 유지
- 히어로 아래 `핵심 시장 브리핑` 3건 추가
  - 현재 시장 선두 최고금리
  - 최근 30일 최대 최고금리 변동
  - 현재 비교군의 상위 10% 진입 최고금리
- 기존 시장 KPI / 경쟁사 TOP 5 / 본점 소재지별 분포 유지
- 시장변화는 raw variant 건수가 아니라 상품 변경 이벤트 수로 표시
  - 동일 run + product + 이전 max_rate + 현재 max_rate는 1건
  - 영향받은 세부 관측 수는 별도 보조정보로 표시
- 신상품 시뮬레이터에 시장 포지션 게이지 추가
  - 시장 평균
  - 중앙값
  - 제안 최고금리
  - 제안금리가 비교상품 범위를 벗어나도 보이도록 표시 범위를 자동 확장
- 예상 수신액은 기존과 동일하게 사용자 가정 기반 WHAT-IF로만 표시

## 2026-08-13 디자인 고도화

이번 패스는 데이터 계약을 바꾸지 않고 `strategy.html`의 표현 계층만 다듬는다.
실제 운영 DB와 canonical `data/table.json` 바인딩은 그대로 유지한다.

### 데스크톱

- 분석업무용 정보 밀도를 유지한 2열 레이아웃
- sticky glass header와 검색·조회 / 전략 대시보드 2메뉴 유지
- 핵심 브리핑 → 시장 KPI → TOP 5/지역 → 시장변화/우대조건 → 시뮬레이터 순으로
  정보 위계를 명확히 한다.
- 기존 muted green / gold 중심으로 색을 낮추고 밝은 카드의 입체감을 강화한다.
- 기존 `collection_health.overall`을 상단에 표시해 데이터 상태를 함께 확인한다.

### 태블릿

- 약 1180px 이하에서 주요 2열 콘텐츠를 자연스럽게 1열로 전환한다.
- 브리핑과 KPI는 2열을 거쳐 1열로 축소해 읽기 순서를 유지한다.
- 지도·시장변화·시뮬레이터는 폭 부족 시 세로 흐름으로 재배치한다.

### 모바일

- 약 620px 이하에서 카드 패딩, 제목, 네비게이션, 수치 크기를 별도로 축소한다.
- 경쟁사 TOP 5는 가로 스크롤 표 대신 상품별 카드형 행으로 바꿔
  기관/상품/기본/우대/최고금리를 한 화면에서 읽을 수 있게 한다.
- 지역 분포, 시장 변화, 우대조건, 시뮬레이터 입력은 모바일 폭에 맞게 재배치한다.
- `viewport-fit=cover`와 `prefers-reduced-motion`을 적용한다.

### 실제 데이터 표현

- 시장 변화의 기존 상승/하락 실제 집계값을 비율 바로도 표현한다.
- 시장 변화 상품 이벤트 수와 `affected_variant_count`를 함께 보여준다.
- 경쟁사, 상품, 최고금리, 지역, 우대조건, 순위는 목업값이 아니라
  실제 Preview build가 복원한 운영 DB와 외부 `data/table.json`에서 계산한다.
- 시뮬레이터의 기본금리/우대금리 기본값은 사용자가 조정하는 WHAT-IF 입력값이며
  실제 시장 데이터로 오인하지 않도록 시장 데이터 카드와 시각적으로 분리한다.

## Acceptance

- 핵심 브리핑이 실제 비교상품과 변경이력에서 계산된다.
- 상위 10% 진입선은 현재 수집 범위의 고유 기관·상품 대표 최고금리에서 계산된다.
- 시장 포지션 게이지가 평균/중앙값/제안금리의 상대 위치를 표시한다.
- 시장 변화 피드에서 동일 상품 variant 동시 변경은 한 상품 이벤트로 보인다.
- 사용자 가정이 없으면 예상 수신액 숫자를 만들지 않는다.
- 데스크톱/태블릿/모바일 반응형 CSS가 하나의 실제 데이터 화면에 적용된다.
- 모바일 TOP 5가 가로 표가 아닌 카드형 행으로 재배치된다.
- 인라인 JavaScript가 `node --check`를 통과한다.
- 전체 Ruff / pytest / empty DB migration CI가 통과한다.
- Preview 빌드가 canonical 운영 DB를 읽기만 하고 isolated preview branch를 갱신한다.
