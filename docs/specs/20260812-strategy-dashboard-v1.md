# 수신상품 전략 대시보드 v1 — 병렬 실험 명세

```yaml
document_type: implementation_spec
status: experimental
created_at: 2026-08-12
target_repository: dekt-oss/bank-rate-collector
inherits_product_contract: docs/specs/20260806-rate-monitor-v4.md
inherits_data_contract: docs/specs/20260805-rate-monitor-v3.1.md
```

## 1. 목적

현재 `site-public/index.html`은 **검색·조회·원자료 확인**에 집중한다. 이 화면을
대체하지 않고, 같은 발행 데이터로 **경쟁사 현황·시장 변화 감지·신상품 금리
시뮬레이션**을 수행하는 별도 전략 화면을 병렬 개발한다.

초기 경로는 `strategy.html`이다. 안정화 전에는 메인 진입점으로 바꾸지 않는다.

```text
index.html       검색·조회 (현행 유지)
strategy.html    전략 대시보드·시뮬레이션 (실험)
```

두 화면은 별도 DB나 별도 수집 파이프라인을 만들지 않는다.

```text
Collectors → canonical SQLite → build_summary / table.json
                                 ↙              ↘
                         index.html        strategy.html
```

## 2. 사용자와 핵심 질문

주 사용자는 저축은행 수신상품 현황 조사 및 상품기획 담당자다.

전략 화면은 아래 질문에 한 화면에서 답하는 것을 목표로 한다.

1. 지금 저축은행 12개월 정기예금 시장의 최고·대표 금리 수준은 얼마인가?
2. 경쟁사 상위 상품은 무엇인가?
3. 최근 30일 동안 금리 변경이 얼마나 발생했고, 어느 상품이 움직였는가?
4. 새 상품의 기본·우대금리를 정하면 현재 수집 범위에서 대략 몇 위인가?
5. 기준 수신액과 금리 민감도를 사용자가 가정하면 수신액 시나리오는 어떻게 변하는가?

## 3. 화면 구조

상단 메뉴는 최소화한다.

```text
[검색·조회] [전략 대시보드]
```

전략 대시보드 기본 배치:

```text
제목 / 데이터 기준시각 / 데이터 상태

[시장 최고금리] [시장 평균 최고금리] [12개월 관측 규모]

[경쟁사 TOP 5                       ] [본점 소재지별 금리 분포]

[최근 30일 시장 변화 감지           ] [우대조건 트렌드]

[신상품 기획 시뮬레이터                               ]
  기본금리 / 우대금리 / 예상 최고금리
  현재 시장 예상 순위 / 상대 경쟁력
  가정 기반 예상 수신액
```

디자인은 짙은 차콜 배경 위에 밝은 floating card를 올리는 bento 구조로 한다.
메뉴보다 숫자·비교·시뮬레이션을 시각적 중심에 둔다.

## 4. 기본 비교 Universe

전략 화면 v1의 기본 비교군은 다음으로 고정한다.

```text
업권        저축은행 (`sector = savings_bank`)
상품유형    정기예금 (`product_type = term_deposit`)
가입기간    12개월
금리기준    최고금리 (`max_rate`)
```

`max_rate IS NULL`인 행을 기본금리로 대체하여 순위를 만들지 않는다. 현재 데이터
계약의 NULL 의미를 그대로 지킨다.

화면에 표시하는 시장 순위·최고값은 반드시 **“현재 수집 범위 내”**라는 분모를
함께 표시한다. 전국 시장 전체를 대표한다고 표현하지 않는다.

## 5. 경쟁사 현황

`data/table.json`의 현재 발행 데이터를 사용한다.

동일 기관·상품·12개월 조합에 가입채널/이자방식 등 복수 관측이 있으면 화면의
경쟁사 요약에서는 그 조합의 `max_rate` 최고값 하나를 대표로 사용한다.
원자료는 삭제하거나 수정하지 않는다.

표시:

- 시장 최고 최고금리
- 시장 평균 최고금리
- 중앙값
- 비교 가능한 고유 기관·상품 수
- 경쟁사 TOP 5
- 기관명 / 상품명 / 기본금리 / 최고금리 / 우대폭

## 6. 시장 변화 감지

관측값은 값이 바뀔 때만 새 `rate_observations` 행이 생기는 현행 변경이력 계약을
이용한다.

v1에서는 **최근 30일 저축은행 12개월 정기예금 최고금리 변경**을 집계한다.

- 이전·현재 `max_rate`가 모두 존재하는 변경만 상승/하락 비교에 사용한다.
- 단순 신규 상품은 금리 상승으로 세지 않는다.
- `validation_status = error`는 제외한다.
- 최근 변경 건수, 상승/하락 건수, 대표 변경 항목을 제공한다.
- 변경 항목에는 기관, 상품, 변경 전/후 최고금리, 증감폭, 변경 감지시각을 표시한다.
- 동일 수집 실행에서 같은 상품의 가입채널·이자방식 등 여러 variant가 **같은
  전후 최고금리로 함께 변경**되면 대시보드에서는 상품 변경 1건으로 집계한다.
- 같은 상품이라도 수집 실행이 다르거나 전후 금리가 다르면 별도 변경 이벤트로
  보존한다. 원본 `rate_observations`는 합치거나 삭제하지 않는다.

따라서 화면의 `변경 감지` 건수는 raw variant 변경행 수가 아니라
`run + product + 이전 max_rate + 현재 max_rate`로 식별한 **상품 변경 이벤트 수**다.
이 집계는 시장 전체 상품 출시량이나 시장점유율을 의미하지 않는다.

## 7. 신상품 시장 순위 시뮬레이션

사용자가 입력한다.

```text
기본금리
우대금리
```

```text
예상 최고금리 = 기본금리 + 우대금리
```

현재 비교 Universe의 고유 기관·상품 대표 최고금리와 비교하여:

```text
예상 순위 = 1 + (예상 최고금리보다 높은 대표 상품 수)
```

동률은 같은 순위로 본다. 화면에는 반드시 분모를 같이 적는다.

```text
예: 현재 수집 범위 73개 비교상품 중 예상 6위
```

`A/B/C/D` 경쟁력 등급은 공식 등급이 아니라 현재 순위 백분위의 화면용 상대지표다.
그 사실을 UI에 적는다.

## 8. 예상 수신액 — v1은 예측모델이 아니라 가정 시나리오

현재 저장소에는 상품별 실제 수신 유입액과 금리 탄력성을 학습할 수 있는 실적
데이터가 없다. 따라서 v1에서 임의의 “예상 수신액”을 생성하지 않는다.

대신 사용자가 두 값을 직접 입력하는 **가정 기반 시나리오 계산기**를 둔다.

```text
B = 기준 월 수신액(억원)
S = 금리 +0.10%p당 수신액 변화율(%) — 사용자가 가정
R = 제안 최고금리
M = 현재 시장 평균 최고금리

격차 단위 = (R - M) / 0.10
예상 수신액 = B × max(0, 1 + 격차 단위 × S / 100)
```

B 또는 S를 입력하지 않으면 금액 결과를 표시하지 않고 `가정 입력 필요`로 둔다.

화면에는 다음 문구를 항상 붙인다.

> 내부 실적 기반 예측모형이 아닙니다. 입력한 기준 수신액·금리 민감도 가정에
> 따른 시나리오입니다.

향후 실제 수신실적·캠페인·채널·기간 데이터를 연결한 뒤 별도 예측모형으로
교체한다.

## 9. 지역 표시

저축은행 지역은 지점 적용금리가 아니라 본점 소재지 근거일 수 있으므로 지도/지역
카드 제목에 **본점 소재지 기준**을 명시한다. 지역 분포를 지점별 적용금리로
표현하지 않는다.

## 10. 기존 화면 보존

공식 사이트의 기본 빌드에서는 전략 화면을 공개하지 않는다. 공개 gate가 켜진
빌드에서만 `site.html`에 전략 화면으로 이동하는 작은 메뉴 링크를 추가한다.

금지:

- 기존 필터·정렬·조회 로직 변경
- 기존 기본값 변경
- DB/schema 변경
- collector 변경
- 별도 데이터 복제
- 기존 `index.html`을 전략 화면으로 교체

## 11. 빌드·배포 및 공개 gate

현행 `build-site`가 `site-public/`을 만드는 구조를 유지한다. 다만 **코드 병합과
사용자 공개를 분리**한다.

### 기본값 — 공식 발행은 OFF

환경변수 `RATE_MONITOR_STRATEGY_DASHBOARD`가 없으면 기존 검색·조회 산출물만
만든다.

```text
site-public/
  index.html
  data/table.json
  ...
```

이 상태에서는:

- `strategy.html`을 만들지 않는다.
- `data/strategy-table.json`을 만들지 않는다.
- `index.html`에 전략 대시보드 링크를 넣지 않는다.
- 같은 출력 디렉터리에 과거 `strategy.html` 또는 `data/strategy-table.json`이
  남아 있으면 삭제한다.

따라서 기능 코드가 `main`에 존재하는 것만으로 전략 화면을 공개하지 않는다.

### Preview / 최종 공개 — 명시적으로 ON

다음 값을 명시한 빌드에서만 전략 화면을 발행한다.

```text
RATE_MONITOR_STRATEGY_DASHBOARD=1
```

```text
site-public/
  index.html
  strategy.html
  data/table.json
  data/strategy-table.json
  ...
```

두 HTML은 같은 canonical 빌드에서 파생된 lightweight page data를 공유한다.
`index.html`은 기존 `data/table.json`을 그대로 사용하고, `strategy.html`은
`data/table.json`에서 **저축은행·정기예금·6/12/24/36개월 행만 필터한**
`data/strategy-table.json`을 사용한다. 전략 slice는 별도 수집·DB 조회·값 변환·
집계 결과가 아니며 기존 압축 배열 `{columns, lookups, rows}` 형식과 원자료 값을
그대로 유지한다. stable `product_id` 증강도 기존 전략 데이터 계약을 그대로 따른다.

`strategy.html`에 전체 금리표나 전략 slice를 인라인하지 않는다.

### 개발 Preview

`feat/strategy-dashboard-*` 브랜치 변경은 별도 workflow가 현재 canonical 운영 DB를
**읽기 전용으로 복원**한 뒤 release gate를 ON으로 빌드한다. 결과는
`preview/strategy-dashboard`에만 강제 갱신한다.

Preview workflow는:

- 외부 수집을 실행하지 않는다.
- canonical 운영 DB를 수정하거나 업로드하지 않는다.
- `rate-data`를 쓰지 않는다.
- 공식 Vercel production 경로를 변경하지 않는다.

최종 공개는 별도 release 변경으로 공식 publish 경로에 gate를 켠 뒤 다시
검증하고 진행한다. 사용자 지시 없이 자동 공개하지 않는다.

## 12. v1 완료 기준

- [ ] 기본 공식 빌드에서는 `strategy.html`과 전략 링크가 생성되지 않는다.
- [ ] Preview/release gate ON 빌드에서는 `strategy.html`이 생성된다.
- [ ] OFF 빌드는 이전 실행의 stale `strategy.html`과 `data/strategy-table.json`도 제거한다.
- [ ] 기존 `index.html` 검색·조회 기능을 그대로 유지한다.
- [ ] gate ON 상태에서 상단에서 두 화면을 왕복할 수 있다.
- [ ] 전략 화면이 실제 `data/strategy-table.json`으로 경쟁사 TOP 5와 시장 순위를 계산한다.
- [ ] 최근 30일 시장 변화 집계는 DB 변경이력에서 계산한다.
- [ ] 같은 run·상품·전후금리의 variant 변경은 상품 이벤트 1건으로 집계한다.
- [ ] 수신액은 사용자 가정 없이는 숫자를 만들지 않는다.
- [ ] `strategy.html`에도 전체 금리표나 전략 slice가 인라인되지 않는다.
- [ ] Preview는 canonical 운영 DB를 읽기만 하고 별도 preview branch만 쓴다.
- [ ] 기존 site service·UI 테스트와 신규 전략 화면 테스트가 통과한다.
- [ ] CI lint/test가 통과한다.
