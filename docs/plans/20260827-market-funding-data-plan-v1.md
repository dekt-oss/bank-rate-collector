# 수신시장 데이터 수집·정리 기획서 v1

- Date: 2026-08-27
- Status: Draft for review
- Base: `main@b3ec3ba7e0c03f545c94ea99497598de0c04be2c`
- Scope: **데이터 수집·정규화·검증·저장 기반만**. 화면 구현과 금리-수신 인과모델은 후속 단계.

## 1. 목적

현재 금리수집기는 금융기관·상품별 금리 비교와 전략화면을 제공한다. 다음 단계에서는 단순히 "누가 더 높은 금리를 주는가"를 넘어, **업권별·기관별로 실제 수신자금이 어디로 이동하는지 관측 가능한 데이터 기반**을 만든다.

이번 단계의 목표는 아래 질문에 답할 수 있는 원천 데이터를 안정적으로 수집·정리하는 것이다.

1. 은행·저축은행·신협·광의 상호금융·새마을금고 중 어느 업권으로 자금이 이동했는가?
2. 업권별 월/분기 수신잔액은 얼마나 증가·감소했는가?
3. 같은 기간 업권 대표 수신금리는 어떻게 변했는가?
4. 저축은행·신협·농협 등에서 개별 기관의 예수금/수신규모를 공개자료로 어느 수준까지 추적할 수 있는가?
5. 향후 `금리 변화 ↔ 수신 변화` 분석에 사용할 수 있도록 시점·주기·단위·공표지연을 보존할 수 있는가?

이번 단계에서는 **"금리 +10bp 때문에 수신이 X% 늘었다" 같은 인과 판정은 하지 않는다.** 먼저 관측값과 메타데이터를 신뢰할 수 있게 축적한다.

## 2. 사용자 관점의 최종 가치

수집 기반이 갖춰지면 후속 화면에서 아래와 같은 결과를 만들 수 있다.

### 2.1 업권별 자금이동

예시:

| 업권 | 대표 1년 수신금리 | 전월비 | 수신잔액 | 월간 증감 |
|---|---:|---:|---:|---:|
| 은행 | 3.10% | -5bp | 2,150조 | -8.2조 |
| 저축은행 | 3.62% | +14bp | 104조 | +1.8조 |
| 신협 | 3.70% | +8bp | 160조 | +0.9조 |
| 광의 상호금융 | 3.45% | +3bp | 520조 | +1.2조 |
| 새마을금고 | 3.71% | +15bp | 270조 | +2.1조 |

후속 표현 예시:

> 은행권 수신 감소, 비은행권 순유입. 저축은행·새마을금고의 수신금리 상승과 수신증가가 동행.

### 2.2 개별기관 수신 경쟁력

FISIS/금융공공데이터에서 충분한 기관별 예수금 항목을 확보할 경우:

| 기관 | 12개월 공시금리 | 업권 대비 | 예수금 QoQ |
|---|---:|---:|---:|
| A저축은행 | 3.80% | +18bp | +2.4% |
| B저축은행 | 3.70% | +8bp | +4.8% |

이 데이터는 향후 "금리를 덜 주고도 수신이 더 늘어난 기관"을 식별하는 데 사용한다.

## 3. 이번 기획에서 확정한 범위

### 포함

1. ECOS 업권별 월간 수신잔액·수신금리 시계열 확장
2. FISIS/금융위원회 금융공공데이터 기관별 재무·예수금 데이터 정찰 및 수집 기반
3. 원천별 주기·단위·관측시점·공표시점·기관 식별자 보존
4. 역사 백필과 증분수집 분리
5. raw artifact 보존 및 fail-closed parser
6. 데이터 품질 리포트

### 제외

1. 전략화면 UI 추가
2. `10bp당 수신효과` 등 인과모델
3. 우리회사 내부 수신데이터 연계
4. 시중은행 특판 레이더 구현
5. 특판의 직접 경쟁순위 반영

특판에 대해서는 별도 결정으로 다음 원칙만 보존한다.

- **시중은행 특판:** 직접 경쟁순위가 아니라 `시장 특판 레이더 / 벤치마킹`으로 관리
- **저축은행·신협·새마을금고·농축협 특판:** 직접 경쟁시장 안에서 특판 속성을 별도 관리하는 후속 과제

이번 작업은 기존 구현을 다시 만들지 않는다.

### 4.1 ECOS macro collector 존재

현재 `src/rate_monitor/collectors/bok_ecos/macro_adapter.py`와 `macro_parser.py`가 존재하며, operational source `bok_ecos_macro`로 기존 기준금리 collector와 분리돼 있다.

현재 검증된 ECOS 계약:

#### 은행 신규취급 수신금리

- `121Y002 / BEABAA2` — 저축성수신
- `121Y002 / BEABAA21` — 순수저축성예금
- `121Y002 / BEABAA2118` — 정기예금 1년

#### 비은행 수신 말잔

- `111Y007 / 1120600` — 상호저축은행
- `111Y007 / 1120700` — 신용협동조합
- `111Y007 / 1120800` — 상호금융
- `111Y007 / 1121000` — 새마을금고

현재 adapter는 최근 **48개월**을 조회한다.

### 4.2 의미 경계

ECOS `1120800 상호금융`은 농협·수협·산림조합 단위조합을 포괄하는 **광의 상호금융**이다.

따라서 다음을 금지한다.

```text
ECOS 상호금융 수신잔액 == 현재 nh_local 농·축협 직접 수신잔액
```

후속 화면과 데이터 모델에서도 `broad_mutual_finance` 또는 동등하게 의미가 드러나는 명칭을 사용한다.

### 4.3 저장 위치

현재 ECOS macro 값은 `market_indicators`에 저장된다. 이 테이블은 `indicator_code`, `source_effective_at`, `source_id`, `value`, `unit`, `raw_artifact_id`, `source_locator` 등을 보존한다.

따라서 **업권 전체의 단일 시계열 값은 기존 `market_indicators`를 우선 재사용**한다. 새 테이블을 중복 생성하지 않는다.

공공데이터포털에서 다음 금융통계 API군의 존재는 확인됐다.

- 금융통계국내은행정보
- 금융통계저축은행정보
- 금융통계신용협동조합정보
- 금융통계농업협동조합정보
- 금융통계수산업협동조합정보
- 금융통계산림조합정보

신용협동조합 API는 `basYm`, `fncoCd`, `fncoNm` 기반의 일반현황·재무현황·주요경영지표 구조를 제공하는 것이 확인됐다.

그러나 다음은 **아직 persistence contract로 확정하지 않는다.**

- 저축은행 API의 정확한 endpoint
- 예수금/정기예금/정기적금의 정확한 metric code와 단위
- 실제 관측주기가 월/분기 중 무엇인지
- 데이터 포털의 `업데이트 주기`와 원천 통계의 경제적 관측주기가 같은지
- 최초 시계열과 publication lag

이 항목들은 D0 recon에서 실제 응답으로 검증한 뒤에만 저장 계약에 추가한다.

### 5.3 Tier B — 중앙회 연간/분기 통계

- 신협중앙회: 장기 자금조성·예탁금 구성·지역 구조 분석에 유용
- 새마을금고중앙회: 연간 시장구조·장기 성장률에 유용

연간 데이터는 금리의 월별 반응을 설명하는 데 사용하지 않는다.

용도:

- 3년 CAGR
- 업권/지역 장기 수신 비중
- 수신상품 구성 변화

## 6. 데이터 관리 원칙

### 6.1 관측값과 파생값 분리

DB에 우선 저장할 것은 **원천이 제공한 관측값**이다.

저장:

- 월말/분기말 수신잔액
- 신규취급 가중평균 수신금리
- 기관별 예수금 등 검증된 재무항목

초기에는 저장하지 않고 계산:

- MoM / QoQ / YoY
- 금리 bp 변화
- 시장점유율 변화
- 동월/T+1/T+2 상관

파생값을 원천값과 같은 테이블에 영구 저장해 stale derivative를 만들지 않는다.

### 6.2 관측시점과 수집시점 분리

반드시 구분한다.

- `period_end` / `source_effective_at`: 값이 의미하는 시점
- `observed_at`: 우리가 수집한 시각
- `published_at`: 원천이 제공하면 보존

공표일이 원천에 없으면 추정값을 저장하지 않는다.

### 6.3 주기 보존

월·분기·연 데이터를 같은 의미로 취급하지 않는다.

- M: 금리 변화와 단기 수신 동행 분석
- Q: 기관별 중기 수신 경쟁력
- A: 시장구조·CAGR

### 6.4 단위 보존

원천 단위를 raw metadata에 남기고, 분석용 normalized unit을 명시한다.

예:

```text
source unit = 십억원
normalized unit = trillion_krw
```

기관별 재무데이터는 단위가 확인되기 전까지 환산 저장하지 않는다.

## 7. 권장 데이터 구조

### 7.1 업권 시계열

기존 `market_indicators` 재사용.

예시 indicator code:

```text
bok_savings_bank_deposit_balance
bok_credit_union_deposit_balance
bok_broad_mutual_finance_deposit_balance
bok_kfcc_deposit_balance
bok_savings_bank_term_deposit_1y_rate   # exact code 검증 후
bok_credit_union_term_deposit_1y_rate   # exact code 검증 후
```

### 7.2 개별기관 시계열

FISIS/금융공공데이터의 exact metric contract가 확인되면 별도 `institution_funding_observations` 계열 테이블을 도입한다.

이유:

- `market_indicators`에는 기관 식별자가 없다.
- 금융회사 코드를 이름으로 억지 매핑하면 institution identity를 오염시킬 수 있다.
- 잔액은 `Rate` 타입보다 큰 정밀 숫자 계약이 필요할 수 있다.

상세 스키마는 작업명세서에 정의한다.

## 8. 구현 단계

### D0 — Evidence Recon

먼저 실제 read-only 원천 호출로 contract를 확정한다.

1. ECOS 미수집 대상 exact stat/item code 탐색
2. FISIS/금융공공데이터 저축은행·신협·농협 API 실제 응답 캡처
3. metric code, unit, period, institution code 확인
4. source recon 문서 + JSON evidence 저장
5. production DB write 없음

### D1 — ECOS 확장

1. verified exact series만 `macro_parser.CONTRACTS`에 추가
2. parser contract test
3. raw artifact 보존
4. 역사 backfill 경로 추가
5. 기존 48개월 rolling collection 유지 또는 evidence에 따라 조정

### D2 — 기관별 funding collector

D0에서 예수금/수신 항목이 확인된 업권만 구현한다.

우선순위:

1. 저축은행
2. 신협
3. 농업협동조합
4. 수협/산림조합

새마을금고 개별 금고 수신은 공개 원천 품질이 확인될 때까지 별도 보류한다.

### D3 — 품질 리포트

수집 후 UI 대신 데이터 보고서를 먼저 만든다.

- 최신 관측월
- 시계열 길이
- missing period
- duplicate point
- unit drift
- source schema drift
- 기관 수
- unmapped institution 수
- publication lag(실측 가능한 경우)

## 9. 성공 기준

### ECOS

- 기존 7개 series regression 없음
- 새 series는 exact code evidence 존재
- 최근 최소 24개월 연속성 검증
- 중복 unique key 충돌 없음
- 단위 drift 시 fail-closed
- raw artifact → normalized point 추적 가능

### 기관별 통계

- 기관 코드 기반 식별
- 이름만으로 existing institution에 자동 병합하지 않음
- 예수금/수신으로 검증된 metric만 저장
- unit/frequency/source period 보존
- 최소 2개 시점 이상의 동일 metric continuity 확인

### 운영

- 기존 금리 수집 경로와 source precedence에 영향 없음
- stable product identity/dedupe 변경 없음
- Strategy 계산식 변경 없음
- UI 변경 없음

## 10. 후속 분석에서 만들 지표

이번 단계 완료 후 별도 기획에서 다음을 계산한다.

1. 업권별 월간 수신증감액/증감률

## 12. 이번 문서의 결론

수신시장 분석을 위한 첫 구현은 **새로운 화면이 아니라 데이터 기반 확장**으로 진행한다.

가장 먼저 ECOS에 이미 존재하는 월별 업권 수신잔액 수집을 유지하면서 부족한 업권 금리·은행 종별수신 시계열을 보강한다. 그다음 FISIS/금융공공데이터를 통해 개별 저축은행·신협 등 기관 단위 수신 데이터를 검증된 항목만 추가한다.

이 단계가 안정화된 후에만 `업권별 자금이동`, `금리-수신 동행`, `기관별 수신 경쟁력` 화면을 설계한다.
