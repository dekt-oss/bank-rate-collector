## 0. 결론

본 시스템은 단순 금리 스크래퍼가 아니라 다음 세 기능이 결합된 **수신상품 시장조사 데이터베이스**로 설계해야 한다.

1. **수집**: 은행·저축은행·새마을금고·신협·지역농축협의 공식 공시를 자동 또는 반자동으로 수집한다.
2. **표준화**: 기관, 지역, 상품, 가입기간, 가입채널, 기본금리, 최고금리, 우대조건을 하나의 비교 기준으로 정규화한다.
3. **관리**: 원본 공시는 보존하고, 사용자가 필요한 형태로 수정·추가·숨김·분류한 값을 별도 편집 계층으로 관리한다.

초안에서 가장 크게 변경할 사항은 저장 구조다. JSON 스냅샷은 초기 시연에는 가능하지만, 지역별 기관·기간별 금리·우대조건·시점 이력·수기 수정이 결합되면 조회와 정합성 관리가 급격히 어려워진다. 따라서 **MVP부터 SQLite를 사용**한다. SQLite는 별도 서버가 필요 없으면서도 관계형 조회, 이력, 충돌 검출, 백업이 가능하다.

또한 농축협은 중앙에서 모든 지역농축협의 수신금리를 동일 형식으로 제공하는 소스가 확인되기 전까지 **완전 자동·전수 수집을 약속하지 않는다.** P0 정찰에서 중앙 상품몰, 개별 농축협 홈페이지, 파일 수집 중 실제 가능한 방식을 결정하고, 화면에는 소스별 수집 완전도를 표시한다.

## 1. 제품 정의

### 1.1 한 줄 정의

시장조사 담당자가 여러 금융기관 사이트를 순회하지 않고, 부산 지역을 중심으로 수신상품 금리를 기관·상품·지역·기간·가입방식별로 비교하고, 공시 원본을 훼손하지 않은 채 내부 조사 기준에 맞게 편집·누적·내보낼 수 있는 금리 모니터링 시스템.

### 1.2 해결하려는 문제

현재 방식은 다음 문제가 발생한다.

- 금융권역별 공시 위치와 조회 방식이 서로 다르다.
- 같은 상품이라도 가입기간, 가입채널, 금액구간에 따라 금리가 다르다.
- 새마을금고·신협·지역농축협은 기관과 지역이 세분화되어 단순 회사명 비교로는 부족하다.
- 최고금리만 비교하면 실제 달성하기 어려운 우대조건을 놓친다.
- 수집 후 내부 기준으로 가공한 데이터가 재수집 시 사라지거나 원본과 섞인다.
- 공시 구조가 변경되면 잘못된 데이터가 조용히 저장될 위험이 있다.
- 어느 기관·지역이 수집되지 않았는지 알 수 없어 화면이 완전해 보이는 착시가 생긴다.

### 1.3 사용자 가치

- 부산 구·군별 경쟁 금리 현황을 한 화면에서 확인
- 기본금리와 최고금리를 분리해 실질 경쟁력 판단
- 우대조건 난이도와 유형을 함께 비교
- 특판 및 수기 조사값을 공식 공시와 구분해 관리
- 특정 기관의 금리 변경 이력과 시장 내 순위 변화 추적
- 현재 조회 결과를 내부 보고용 엑셀로 즉시 산출

## 3. 핵심 설계 원칙

### 3.1 원본·표준화·편집의 3계층

```text
공식 공시 원본
    ↓ 보존
원본 관측값(raw observation)
    ↓ 파싱·정규화
표준 비교 데이터(canonical data)
    ↓ 사용자 편집을 겹쳐 표시
업무용 표시 데이터(effective data)
```

- **원본 관측값**: 수집 당시 응답, 파일, HTML, 조회조건, 해시를 보존한다.
- **표준 비교 데이터**: 기관·상품·기간·금리·우대조건을 통합 스키마로 변환한다.
- **업무용 표시 데이터**: 수기 수정, 추가, 숨김, 메모, 내부 분류를 적용한 최종 화면값이다.

### 3.2 이름이 아니라 원천 식별자를 우선 사용

기관명과 상품명은 바뀔 수 있다. 가능한 경우 중앙회나 공시 소스가 제공하는 기관코드·점포코드·상품코드를 사용한다.

식별자 우선순위:

1. 공식 원천 시스템의 고유 코드
2. 원천 코드 조합
3. 기관명·주소·지역을 정규화한 복합키
4. 수기 별칭 매핑

### 3.3 기관과 지점을 분리

새마을금고·신협·농축협은 법인 또는 조합 단위의 기관과 본점·지점이 다르다.

- `institution`: 금리를 결정하거나 상품을 판매하는 법인·조합
- `outlet`: 실제 본점·지점·영업점
- `rate_scope`: 금리가 기관 공통인지, 특정 지점인지, 전국 공통인지 표시

지점이 여러 개라고 같은 기관 금리를 중복 행으로 만들지 않는다. 다만 공시가 지점별 금리를 제공하면 지점 단위 상품으로 저장한다.

### 3.4 소재지와 가입 가능 지역을 분리

- `institution_region`: 기관 소재지
- `outlet_region`: 지점 소재지
- `availability_scope`: 전국, 해당 조합원, 특정 지역, 직장 구성원, 미확인

부산 필터는 단순히 본점 주소만 보는 것이 아니라, 화면에서 **기관 소재지 기준**과 **부산 가입 가능 상품 기준**을 구분할 수 있게 한다.

### 3.5 최고금리를 그대로 경쟁력으로 간주하지 않음

최고금리는 모든 우대조건을 충족해야 하는 값일 수 있다. 따라서 다음 값을 함께 제공한다.

- 기본금리
- 최고금리
- 우대폭
- 우대조건 개수
- 우대조건 유형
- 우대조건 구조화 상태
- 사용자 평가 난이도: 쉬움·보통·어려움·미평가
- 조건 없는 최고금리 여부

## 4. 공식 수집원 전략

### 4.1 수집원 우선순위

1. 공식 API
2. 공식 사이트의 공개 조회 요청 또는 공식 다운로드 파일
3. 공식 사이트의 브라우저 자동화
4. 공식 사이트에서 사용자가 다운로드한 파일 수입
5. 개별 기관 공식 홈페이지의 공시
6. 수기 입력

민간 금리 비교 사이트나 검색 결과 재가공 데이터는 원천으로 사용하지 않는다.

### 4.2 소스별 운영안

| 권역 | 1차 원천 | 보조 원천 | 초기 수집 방식 | 주요 검증사항 |
|---|---|---|---|---|
| 은행 | 금융감독원 금융상품 비교공시 API | 금융회사 공식 공시 | 자동 API | 페이지네이션·상품옵션 결합 |
| 저축은행 | 저축은행중앙회 소비자포털 | 금융감독원 API | 공식 조회/엑셀 우선, API 교차검증 | 기본·최고금리, 가입방법, 공시일 |
| 새마을금고 | 새마을금고중앙회 금고위치·금리안내 | 개별 금고 공식 페이지 | 공개 요청 자동화 후보 | 금고·점포 코드, 상세금리 페이지 구조 |
| 신협 | 신협중앙회 예금 금리비교 | 신협찾기·개별 신협 페이지 | 공개 조회 자동화 후보 | 지역·하위지역·가입방식·상세조건 |
| 지역농축협 | 농협 공식 상품몰·개별 농축협 공식 홈페이지 | 수기 파일 | P0 확인 전 혼합형 | 중앙 전수조회 가능 여부, 사이트별 표준성 |

### 4.3 저축은행중앙회 처리 원칙

사용자 요구에 따라 저축은행중앙회 소비자포털을 저축은행 금리의 1차 원천으로 사용한다.

- 조회조건: 조회일, 가입기간, 가입방법, 이자계산방식
- 수집필드: 저축은행, 상품명, 기본금리, 최고우대금리, 상세조건, 공시기준일
- 가능한 경우 공식 엑셀 다운로드를 자동 획득하고, 불가능하면 사용자가 받은 엑셀을 `inbox`에 넣어 파싱한다.
- 금융감독원 API 데이터는 누락 및 값 차이 탐지용 보조 소스로 사용한다.
- 포털 공시는 본점 기준일 수 있으므로, 이를 지점·지역별 금리로 오해하지 않도록 `rate_scope=head_office_reference`로 표시한다.

### 4.4 새마을금고 처리 원칙

새마을금고 위치·금리안내는 시도→시군구→금고·점포 구조와 금리 상세 페이지를 제공하므로 부산 구별 수집의 핵심 소스로 사용한다.

- 공식 금고 코드와 점포 코드가 확인되면 영구 식별자로 저장
- 직장금고는 일반 고객 이용 제한을 별도 표시
- 동일 금고의 여러 점포가 동일 금리를 공유하면 기관 단위 한 건으로 통합
- 상세 페이지에 금액구간별 금리가 있으면 구간별 상품옵션으로 분리

### 4.5 신협 처리 원칙

신협 금리비교 화면은 지역·하위지역·가입방식과 기본·최고우대금리를 제공하므로 자동화 후보로 분류한다.

- 거치식·적립식 상품을 구분 수집
- 지역·하위지역 조회값과 신협찾기의 기관 주소를 매핑
- 상세정보에서 우대조건 원문을 확보
- 조합명만으로 식별하지 않고 가능하면 조합 코드 또는 공시 내부 키를 저장

### 4.6 지역농축협 처리 원칙

지역농축협은 초안에서 가장 불확실한 영역이다. 공식 농협 사이트에 농·축협 상품 영역과 개별 조합 홈페이지가 존재하지만, 모든 조합의 수신금리를 지역별로 일괄 비교할 수 있는 중앙 공개화면이 실제로 제공되는지는 별도 검증이 필요하다.

P0에서 다음 순서로 조사한다.

1. 농·축협 공식 상품몰의 지역·조합별 금리 요청 존재 여부
2. 조회 요청이 공개 상태에서 재현 가능한지 확인
3. 부산 소재 농축협 홈페이지의 금리표 구조 표본 수집
4. 표준 구조가 아니면 조합별 어댑터가 아닌 `HTML table / Excel / manual` 범용 수입기를 우선 개발
5. 화면에 `수집완전도=부분`을 명시하고 미수집 기관 목록을 제공

농축협 데이터를 확보하지 못했다고 임의로 전국평균금리나 대출 기준금리를 수신상품 금리로 대체하지 않는다.

### 4.7 2026-08-05 공식 화면 확인 결과

- 저축은행중앙회 소비자포털은 정기예금 화면에서 조회일·가입기간·가입방법·단리/복리를 제공하고, 기본금리와 최고우대금리 및 엑셀 다운로드 영역을 제공한다. 다만 화면 안내상 본점 기준 공시이므로 지역별 지점금리로 해석해서는 안 된다.
- 새마을금고 공식 위치·금리 안내는 시도와 시군구를 선택해 금고·점포를 조회하며, 목록에 금고 및 점포 식별에 활용 가능한 코드성 값과 상세 금리 이동 경로가 노출된다.
- 신협 공식 예금 금리비교는 거치식·적립식, 지역·하위지역, 창구·인터넷·모바일 가입방식, 기본금리·최고우대금리 비교 구조를 제공한다.
- 농협 공식 웹 영역에는 농·축협 상품 구분과 개별 농축협의 공식 금리표가 존재하지만, 부산 전체 조합을 동일 형식으로 비교하는 중앙 공개 수신금리 화면은 본 문서 작성 시점에 확정하지 못했다. 따라서 P0 필수 검증사항으로 유지한다.

## 5. 표준 데이터 모델

### 5.1 핵심 엔터티

| 엔터티 | 목적 |
|---|---|
| `source` | 공식 수집원과 자동화 정책 |
| `collection_run` | 수집 실행 단위와 성공·실패·건수 |
| `raw_artifact` | 원본 응답·HTML·엑셀·해시·조회조건 |
| `institution` | 은행·저축은행·금고·신협·농축협 법인/조합 |
| `outlet` | 본점·지점·영업점 |
| `product` | 상품의 기본 정체성 |
| `product_variant` | 기간·채널·금액구간·이자방식별 옵션 |
| `rate_observation` | 특정 기준일의 금리 관측값 |
| `preference_condition` | 우대조건 구조화 결과 |
| `manual_override` | 사용자 수정·추가·숨김·메모 |
| `entity_alias` | 이름 변경·중복·통폐합 매핑 |
| `change_event` | 이전 관측 대비 변화 |

### 5.2 상품 식별 구조

단일 `RateRecord` 해시만으로 모든 것을 식별하지 않는다.

```text
기관(institution)
  └─ 상품(product)
       └─ 상품옵션(product_variant)
            └─ 시점별 금리(rate_observation)
```

#### 상품옵션을 나누는 기준

- 가입기간
- 가입채널
- 이자계산방식
- 정액·자유적립 방식
- 최소·최대 가입금액
- 금액구간
- 대면·비대면 전용 여부
- 개인·법인 등 가입대상

### 5.3 필수 금리 필드

| 필드 | 설명 |
|---|---|
| `base_rate` | 우대조건 제외 기본금리 |
| `max_rate` | 공시상 최고 우대금리 |
| `pref_spread` | `max_rate - base_rate`, 계산값 |
| `rate_unit` | 기본 `%`, 향후 별도 단위 방지 |
| `rate_basis` | 연이율, 세전 등 기준 |
| `amount_min`, `amount_max` | 금액구간 |
| `term_months`, `term_days` | 가입기간 |
| `interest_method` | 단리·복리·기타 |
| `as_of` | 공시 기준일 |
| `valid_from`, `valid_to` | 특판 또는 적용기간 |

금리 파싱 실패를 `-1`로 저장하지 않는다. 숫자 컬럼은 `NULL`로 두고 `validation_status=error`, `validation_message`를 저장한다. 음수 금리가 실제로 존재할 수 있는 장기 확장성을 고려해 오류 표시값과 실제 값의 의미를 섞지 않는다.

### 5.4 우대조건 표준화

우대조건은 원문을 항상 보존하고, 가능한 부분만 구조화한다.

- 거래기간·장기고객
- 조합원·출자금
- 특정 연령·직군·대상
- 만기 유지
- 이벤트·특판

#### 구조화 필드

## 7. 자동 모니터링 운영

### 7.1 수집 주기

기본값은 설정으로 관리한다.

| 수집원 | 권장 기본 주기 |
|---|---|
| 금융감독원 API | 매일 1회 |
| 저축은행중앙회 | 영업일 매일 1회 |
| 새마을금고 | 영업일 매일 1회 또는 주 3회 |
| 신협 | 영업일 매일 1회 또는 주 3회 |
| 농축협 | 소스별 주기, 초기 주 1회 |
| 수기 파일 | 파일 투입 즉시 또는 수집 실행 시 |

수집 주기는 서버 부하와 공시 갱신 빈도를 확인한 후 조정한다. 짧은 간격 반복 호출은 금지한다.

### 7.2 수집 실행 상태

- `success`: 정상 수집·검증 완료
- `partial`: 일부 지역·페이지 실패
- `no_change`: 정상이나 변경 없음
- `blocked`: 접근 제한·인증·정책 문제
- `schema_changed`: 원천 구조 변경
- `failed`: 네트워크·파서 오류

### 7.3 변경 감지

변경 이벤트 유형:

- 기본금리 상승·하락
- 최고금리 상승·하락
- 우대조건 추가·삭제·변경
- 상품 신규·판매중단
- 가입채널 변경
- 특판 시작·종료
- 기관·지점 정보 변경

동일한 관측값을 매일 중복 저장하지 않고, 관측 실행과 유효 데이터 버전을 분리해 저장용량을 줄일 수 있다.

### 7.4 알림

MVP 이후 다음 조건을 지원한다.

- 특정 권역·구의 최고금리 변경
- 지정 기관의 금리 변경
- 경쟁사보다 일정 %p 이상 높은 상품 등장
- 특판 종료 임박
- 수집 실패 또는 구조 변경

## 8. 데이터 품질 기준

### 8.1 필수 검증

- 기관 식별자 존재
- 상품명 존재
- 상품유형 존재
- 기간 또는 입출금자유 여부 존재
- 기본금리·최고금리 숫자 형식 검증
- 최고금리 < 기본금리인 경우 경고
- 공시일이 미래인 경우 오류
- 동일 기관·상품옵션·기준일 중복 검사
- 원문 또는 원본 파일 추적 가능

### 8.2 수집완전도

화면에서 다음을 구분한다.

- `complete`: 목표 기관·지역 전부 수집
- `high`: 90% 이상
- `partial`: 일부 기관만 수집
- `manual`: 수기 자료만 존재
- `unknown`: 모집단 자체가 확정되지 않음

수집완전도는 전체 레코드 수가 아니라 **목표 기관 목록 대비 실제 수집 기관 수**로 계산한다.

### 8.3 구조 변경 탐지

각 수집기는 다음 구조 지문을 저장한다.

- 헤더명과 순서
- 주요 HTML 선택자
- 응답 JSON 키
- 파일 시트명
- 필수 컬럼 수

지문이 바뀌면 잘못된 빈 데이터로 저장하지 않고 `schema_changed`로 중단한다.

## 9. 기술 형태

### 9.1 기본 구성

- 백엔드: Python + FastAPI
- 저장소: SQLite
- ORM/스키마: SQLAlchemy 또는 SQLModel + Alembic
- 수집: HTTP 클라이언트, 공식 API, 필요 시 Playwright
- 파싱: BeautifulSoup/lxml, openpyxl
- 스케줄: CLI 수집 명령 + 운영체제 스케줄러; 앱 실행 중 보조 스케줄러 가능
- 프론트: 서버 렌더링 + 경량 JavaScript, 편집 가능한 데이터 그리드
- 엑셀: openpyxl
- 배포: 로컬 실행 또는 단일 서버 Docker Compose

### 9.2 SQLite를 MVP부터 사용하는 이유

- 기관·상품·옵션·시점·편집 이력의 관계를 보존
- 부산 구별·기간별 복합 필터를 빠르게 처리
- 재수집 시 upsert와 중복 방지
- 수정 충돌과 감사 로그 관리
- 파일 하나로 백업 가능
- 향후 PostgreSQL로 옮기기 쉬움

### 9.3 서버 전환 조건

다음 중 하나가 발생하면 PostgreSQL과 사용자 인증을 검토한다.

- 동시 사용자 3명 이상
- 외부 네트워크에서 상시 접속
- 전국 전수 수집
- DB 2GB 이상
- 수집 작업과 조회 작업의 동시 부하 증가
- 승인·역할·감사 요구 발생

- 저축은행 수집기
- 새마을금고 수집기
- 신협 수집기
- 농축협 가능한 방식의 첫 어댑터

통과 기준:

- 동일 자료 재수집 시 중복 없음
- 모든 레코드에서 원본 추적 가능
- 부산 목표 기관 대비 수집완전도 산출 가능

### P2. 통합 비교 화면

- 통합 그리드
- 지역·상품·기간·가입방식 필터
- 기본·최고·우대폭 비교
- 상세 패널
- 엑셀 내보내기

통과 기준:

- 사이트 순회 없이 부산 경쟁 금리 조사를 완료
- 오류·미수집 범위를 사용자가 식별 가능

### P2.5. 업무 편집

통과 기준:

## 11. 성공 기준

### 기능 성공 기준

- 부산 16개 구·군 필터가 정확히 작동
- 4개 핵심 권역을 한 화면에서 비교
- 기본금리·최고금리·우대폭·우대조건 원문 제공
- 수집 원본과 수기 수정 구분
- 재수집 후 수정 유지 및 충돌 표시
- 엑셀에 필터 결과·출처·수정 여부 반영
- 미수집 기관과 실패 소스를 숨기지 않고 표시

### 데이터 성공 기준

- 파싱된 금리 정확도 99% 이상: 표본 수기 대조 기준
- 기관 중복률 1% 미만
- 원본 추적 가능률 100%
- 구조 변경 시 오염 저장 0건
- 부산 목표 기관 수집완전도: 소스별 목표값 별도 설정

### 업무 성공 기준

- 기존 수작업 대비 조사시간 60% 이상 감소
- 엑셀 재가공 횟수 감소
- 누락·중복·오래된 공시의 식별 가능

## 13. 확정 기준과 기본값

별도 결정이 없으면 다음을 구현 기본값으로 사용한다.

- 프로젝트명: `rate-monitor`
- 지역: 부산광역시 16개 구·군
- 핵심 권역: 저축은행·새마을금고·신협·지역농축협
- 은행: 선택형 벤치마크
- 저장소: SQLite
- 기본 화면 기준: 현재 유효한 최신 관측값 + 적용된 수기 편집값
- 원본 보존기간: 최소 1년
- 수집 실패 시 이전 정상값 유지, 단 최신성 경고 표시
- 농축협: P0 판정 전 `부분 수집`으로 명시
