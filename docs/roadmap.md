# 남은 작업 — 수집 / 구현 / 운영

기준일 2026-08-05. 이 문서는 **지금 무엇이 되고 무엇이 안 되는지**를 한 곳에
모은다. 세부 근거는 각 정찰 문서에 있다.

되는 것과 안 되는 것을 섞어 적지 않는다. "예정"과 "완료"를 같은 칸에 넣으면
다음 사람이 이미 있는 줄 알고 넘어간다.

---

## 1. 지금 되는 것

| 원천 | 범위 | 실측 |
|---|---|---|
| finlife (금감원) | 저축은행 전국 | 상품 669 / 금리옵션 4,010 |
| 새마을금고 | 전국 17개 지역 (범위 선택 가능) | 금고 1,260 / 점포 3,135 |

새마을금고 수집 범위는 `config/regions.yaml`의 이름으로 고른다 (`전국`·`수도권`
·`부산`). 부산은 이제 수집 단위가 아니라 그 범위 중 하나이고, 화면에서도
시도를 고른 뒤 구·군으로 파고드는 필터일 뿐이다.

Actions에서 `Collect rates`를 돌리면 수집 → 스냅샷 → 검증 → 대시보드 →
내보내기 → 게이트 → `rate-data` 발행까지 자동으로 흐른다.
[run 31000613598](https://github.com/dekt-oss/bank-rate-collector/actions/runs/31000613598)에서
14단계 전부 성공했다.

## 2. 수집이 남은 것

### 2.1 새마을금고 요구불예탁금 (`gubuncode=12`)

화면 구조는 확인했다. 보통예탁금·자유예탁금이고 표에 **단계금액** 열이 있다.

```
상품명 / 단계금액 / 이율
MG행복지킴이통장 / 300,000 미만 / 0.1
                / 300,000 이상 / 0.2
```

금액 구간을 `amount_min`·`amount_max`로 옮기는 파싱이 따로 필요하다. 스키마에
칸은 이미 있다. 명세서 v3 §7.3.10이 완료 조건에 넣었으므로 **미룬 것이지
버린 것이 아니다.**

요청량은 금고당 1회 늘어 137회 추가된다.

### 2.2 저축은행중앙회(FSB) 수집기

정찰이 끝났다 (`docs/source-recon/fsb.md`). 엔드포인트·조회차원·필드 구조를
알고 표본도 있다. 수집기 코드만 없다.

붙이면 finlife에 없는 것이 들어온다 — 가입방법, 우대조건 3종, 만기후이율,
상품 상세 링크. 다만 **여전히 본점 기준이라 구 단위는 안 된다.**

미해소 두 가지가 남아 있다.
- 입출금자유예금(`ratanym_0100.jct`)이 빈 응답만 준다. 원인 미확인.
- 이용약관이 없어 `policy_status`가 `unknown`이다.

### 2.3 신협 · 농축협

정찰조차 하지 않았다. 명세서 §19의 세로 절단 3·4다.

### 2.4 전국 수집 — 열렸으나 아직 한 번도 돌리지 않았다

수집기는 전국을 돌 수 있다 (`--scope 전국`). 요청량은 목록 17 + 금고 1,260 ×
상품군 2 = **2,537회**이고 1초 간격이라 약 42분이다. 예약 실행의 기본값이
전국이지만, 이 문서를 쓰는 시점에 전국 실행 기록은 **없다.** 실제로 돌려
소요시간·차단 여부·저장 용량을 확인하는 것이 남았다.

전국 금고 1,260 / 점포 3,135는 2026-08-05에 목록 페이지를 직접 세어 얻은
값이다 (`config/regions.yaml`의 `observed`). 예전에 적어둔 1,173금고 /
2,970점포는 참고 저장소 집계였다.

**`r1`은 행정구역이 아니다.** `r1=광주`로 조회하면 광주 101 / 전남 124 /
전남광주통합특별시 4가 함께 오고, `r1=전남`은 3건뿐이다. 사이트의 지역본부
묶음에 가깝다. 그래서 지역 표시는 언제나 점포 주소에서 뽑는다
(`parser.split_region`, `dashboard_service.SIDO_EXPR`).

## 3. 구현이 남은 것

### 3.1 스키마만 있고 채우지 않는 테이블

| 테이블 | 무엇 | 왜 비어 있나 |
|---|---|---|
| `preference_conditions` | 우대조건을 조건별로 쪼갠 것 | 지금은 `preference_raw` 원문만 저장한다 |
| `manual_overrides` | 사람이 고친 값 | 오버라이드 병합이 미구현 (세로 절단 5) |
| `entity_aliases` | 기관명 이형 매핑 | 통폐합·개명 처리에 쓸 자리 |

### 3.2 오버라이드 병합 (세로 절단 5)

명세서 v3 §11의 핵심인데 전부 미구현이다. 사람이 고친 값이 자동 수집값을
어떻게 이기는지, 충돌을 어떻게 표시하는지, 변경 이벤트를 어떻게 남기는지.

정적 대시보드에서 편집을 어떻게 받을지부터 정해야 한다. v3.1이 서버를
없애면서 v3의 오버라이드 모델과 어긋난 상태다.

### 3.3 교차대조 (`cross_source_difference`)

같은 저축은행을 finlife와 FSB 양쪽에서 받아 값이 다르면 검수항목을 만든다.
FSB 수집기가 선행이다. 기관코드 체계가 서로 다르다는 것까지만 확인했고
매핑은 아직 없다.

### 3.4 엑셀 내보내기

지금은 CSV와 JSON이다. 명세서 §2가 P2로 밀어뒀다. `openpyxl` 의존성을
일부러 뺀 상태다.

## 4. 운영이 남은 것

### 4.1 원본 1년 보존 — 구조적으로 미충족

명세서 v3 §16.2는 원본 최소 1년 보존을 요구한다. GitHub Artifact 상한이
**90일**이라 (2026-08-05 실측) 그것만으로는 채울 수 없다. 별도 보관소를
정해야 한다.

### 4.2 `rate-data` 브랜치 용량

1회분 1.36 MB. gzip은 git이 델타 압축을 못 해 실행마다 통째로 쌓인다.
일 1회면 연 약 500 MB다. 정리 정책이 필요하다. 후보 둘:

- 주기적으로 브랜치 이력을 잘라 최신 1건만 남긴다
- 이력은 Artifact에 맡기고 브랜치는 최신본 전달로만 쓴다

### 4.3 이용약관 확인

| 원천 | `policy_status` | 상태 |
|---|---|---|
| finlife | `allowed` | 공식 오픈API |
| 새마을금고 | `review` | 약관 미확인 |
| FSB | `unknown` | 사이트 이용약관 자체가 없다 |

정기 수집을 켜기 전에 새마을금고·중앙회에 문의해 확정해야 한다.

### 4.4 행정구역 공식 코드

`config/regions.yaml`의 `sido_code`·`sigungu_code`가 전부 `null`이다.
화면의 구 표시는 **주소에서 뽑은 파생값**이고 공식 코드가 아니다.
`validation_service`가 이 칸이 채워지면 실패하도록 막아두었다 — 화면
파라미터를 공식 코드로 착각해 넣는 것을 방지한다.

### 4.5 GitHub Pages

private 저장소의 Pages 공개 범위를 확인하지 못해 배포하지 않았다.
`collect.yml`에 주석으로 자리만 있다.

### 4.6 Vercel 배포 — 한 단계가 사람 손을 탄다

산출물은 준비돼 있다. `rate-monitor build-site`가 그대로 올릴 수 있는
한 벌을 만들고, 수집 워크플로우가 이것을 `rate-data` 브랜치의
`site-public/`에 밀어 넣는다.

```
site-public/
  index.html          78 KB   요약과 조회 UI
  data/table.json    720 KB   금리표 (부산 16,913행 기준)
  data/table.json.gz
  data/rates.csv     2.1 MB   사람이 받아가는 파일
  data/rates.json    6.4 MB
  vercel.json                 캐시 헤더
  site-manifest.json
```

남은 것은 **Vercel 프로젝트를 이 저장소에 연결하는 일**이다. 저장소가
private이라 Vercel에 접근 권한을 주는 OAuth 승인이 필요하고, 그건 계정
주인만 할 수 있다. 자동화 경로로는 대신 못 한다.

Vercel 대시보드에서:

| 항목 | 값 |
|---|---|
| Git Repository | `dekt-oss/bank-rate-collector` |
| Production Branch | `rate-data` |
| Root Directory | `site-public` |
| Framework Preset | Other |
| Build Command | 없음 (정적 파일) |
| Output Directory | `.` |

연결하고 나면 수집이 돌 때마다 `rate-data`에 push가 일어나고 Vercel이
그걸 받아 자동 배포한다. 별도 배포 단계를 워크플로우에 넣지 않아도 된다.

**MCP `deploy_to_vercel`로는 못 한다.** 그 도구는 파일 내용을 요청 안에
직접 실어 보내는데, 여기 데이터가 9 MB다.

## 5. 알려진 데이터 한계

- **저축은행 금리는 구 단위로 말할 수 없다.** finlife도 FSB도 본점 기준
  공시다. 화면의 구별 집계에 저축은행이 잡히지 않는 것은 의도한 결과다.
- **직장금고**는 해당 직장 임직원만 가입할 수 있다. 구 대표값에서 빼고
  따로 표시한다. 부산에 4곳 있다.
- **구 이름은 전국에서 겹친다.** 중구만 해도 서울·부산·대구·인천·대전·울산에
  있다. 집계·화면·내보내기 모두 시도와 구를 함께 쓴다.
- **`연0.0%`**의 의미가 미확정이다. 실제 0%인지 미취급 표시인지 모른다.
  값 그대로 저장한다.
- **새마을금고에는 우대금리가 없다.** 공식 화면에 열 자체가 없어 `max_rate`가
  항상 비어 있다. `base_rate`로 메우지 않는다.
