## 0. 코드를 추정하지 않고 찾아냈다

v4 §7.2가 못 박는다 — **"확인하지 않은 통계코드를 추정 하드코딩하지 않는다."**
그래서 정찰 스크립트가 코드를 적는 대신 이름으로 찾는다.

```
통계표 834개 중 이름에 '기준금리'·'정책금리'가 든 것 2개

  722Y001  1.3.1. 한국은행 기준금리 및 여수신금리     주기 D   ← 쓴다
  902Y006  9.1.1.3. 국제 주요국 중앙은행 정책금리      주기 M
```

`902Y006`도 한국 3.5%를 준다. 그런데 **월 단위이고 국가 비교용**이다.
정책금리는 바뀐 날짜가 값만큼 중요하므로 일 단위 원천을 쓴다.

```
722Y001 항목 48개 중 '기준금리'가 든 것

  0101000  한국은행 기준금리   주기 A · D · M · Q 모두 제공
```

## 1. 계약

```
GET https://ecos.bok.or.kr/api/StatisticSearch/{인증키}/json/kr/1/{개수}
    /722Y001/D/{시작 YYYYMMDD}/{끝 YYYYMMDD}/0101000
```

응답 (실측, `tests/fixtures/bok_ecos/base_rate_daily.json`):

```json
{"StatisticSearch": {"list_total_count": 947, "row": [
  {"STAT_CODE": "722Y001",
   "STAT_NAME": "1.3.1. 한국은행 기준금리 및 여수신금리",
   "ITEM_CODE1": "0101000", "ITEM_NAME1": "한국은행 기준금리",
   "UNIT_NAME": "연%", "TIME": "20240101", "DATA_VALUE": "3.5"}]}}
```

`TIME`은 주기에 따라 자릿수가 다르다 — 일 8자리, 월 6자리, 연 4자리.

단위는 원천이 **「연%」**로 준다. 명세서 §7.1이 저장 단위를 `percent`로
고정하므로 그 값이 바뀌면 행을 버리고 경고한다 — 단위가 달라지면 화면의
숫자가 뜻을 잃는다.

## 2. 인증키가 **경로에** 들어간다

쿼리스트링이 아니라 URL 자체에 박힌다. finlife의 `auth=`와 같은 문제이고
같은 규율을 적용한다 (v3 §16.1).

- `request_meta.url`은 키를 `[REDACTED]`로 바꿔 저장한다
- 정찰 보고서도 저장 직전에 키를 지운다
- 워크플로가 보고서에 키가 남았는지 한 번 더 검사하고, 남았으면 아티팩트를
  올리지 않는다 — **저장소가 공개다**

2026-08-06 실행에서 「인증키 노출 0건」으로 통과했다.

---

## 3. 오류를 200으로 준다

ECOS는 실패도 HTTP 200으로 돌려주고 본문에 `RESULT`를 담는다. 상태코드만
보면 빈 시계열을 정상으로 받아들이게 되므로 파서가 본문을 본다.

---

## 4. 수집 주기와 중복

하루 1회면 충분하다 (§7.3). 그런데 **기준금리는 몇 달씩 안 바뀐다.**
매일 한 줄씩 쌓으면 이력이 아니라 잡음이 된다.

```
UNIQUE(indicator_code, source_effective_at, source_id)
```

같은 날짜를 두 번 쌓지 않는다. 값이 그대로면 실행이 `no_change`로 끝난다 —
그래야 "받았는데 안 바뀐 것"과 "못 받은 것"이 구별된다.

받는 구간은 400일이다. 최근 한 건만 받으면 그 값이 언제부터인지 모르고,
며칠 못 돌린 사이의 변경도 놓친다.

---

## 5. 아직 확인하지 않은 것

- **공식 기준금리 화면과의 최신값 대조** (§7.5). 정찰은 2024년 구간만
  조회했다. 실제 수집을 돌린 뒤 bok.or.kr의 현재 값과 맞춰 봐야 한다.
- 정책금리 변경일의 반영 시차. 금통위 결정 당일에 ECOS가 갱신되는지
  다음 날인지 모른다.
- 이용약관. ECOS 오픈API는 신청·승인 절차가 있고 사용자가 키를 발급받았다.
  자동수집 제한 조항은 확인하지 않았다.
