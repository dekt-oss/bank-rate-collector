## 1. 가장 중요한 결론부터

**지금까지 확보한 원천 중 지역과 최고 우대금리를 동시에 주는 유일한 곳이다.**

| 원천 | 지역 | 최고 우대금리 |
|---|---|---|
| finlife (금감원) | 없음 | 없음 (`intr_rate2`를 주지만 우리는 신뢰하지 않는다) |
| 저축은행중앙회 | 본점 소재지만 | 있음 |
| 새마을금고 | 있음 (점포 주소) | **열 자체가 없음** |
| **신협** | **있음 (조회 조건)** | **있음** |

새마을금고에서 하지 못한 "우대조건을 다 채우면 얼마"를 신협에서는 말할 수
있다. 실측에서 부산 1,423개 관측 중 **237건이 최고금리 > 기본금리**였다.

다만 신협의 지역은 **조회 조건**이지 점포 주소가 아니다. 새마을금고처럼
구·군까지 내려가지 못한다 (§4).

## 3. 데이터는 HTML에 없다

표는 헤더만 있고 본문은 AJAX로 실린다. 화면 JS가 조립하는 실제 경로:

```
POST /cu/ad/inrstCmpr/findInrst15CmprListResult.do
POST /cu/ad/inrstCmpr/findInrst17CmprListResult.do
POST /cu/ad/inrstCmpr/findInrstSido.do          지역 목록
```

`application/x-www-form-urlencoded`로 POST한다. 화면을 먼저 GET해 세션
쿠키(`JSESSIONID`)를 받아야 한다.

### 3.1 요청 본문 — `fn_find`/`fn_move_query_condition`에서 읽음

```
currPage      1
listMaxCnt    50
highLimtAmt   10,000,000     ← 쉼표 포함. 화면 기본값
monTy         12             ← 저축 예정기간(개월)
sido          AA             ← 전체
subSido       AA             ← 전체
tretChlTy     A              ← 가입방식 전체
sortColumn    CU_NM
sortAsc       A
searchTxt     (빈 값)
```

### 3.2 "전체"는 빈 문자열이 아니라 `AA`다 — 여기서 걸렸다

빈 문자열로 보내면 **오류가 아니라 0건**이 돌아온다. 실제로 정찰 첫 시도에서
`sido=""`, `monTy=""`로 보내 `[]`를 받았고, "이 화면은 데이터가 없다"고
잘못 결론 낼 뻔했다.

화면 JS가 아무것도 선택되지 않으면 `AA`를 넣는다.

```js
if (sido.includes("AA")) $('#h_sido').val('AA');
if ($("input[name=subSido]:checked").length == 0) $('#h_subSido').val('AA');
if (tretChlTy.includes("A")) $('#h_tretChlTy').val('A');
```

`highLimtAmt`도 마찬가지다. 화면 기본값이 `"10,000,000"`(쉼표 포함)이고,
`"10000000"`이나 빈 값으로는 결과가 달라진다.

**빈 결과를 성공으로 저장하면 "취급 상품 없음"과 구분되지 않는다.**

### 3.3 지역 코드

`findInrstSido.do`가 `{"sido": "04", "subsido": "기장"}` 형태로 돌려준다.
시도 코드와 하위지역 **이름**은 주지만 시도 이름은 주지 않는다.

#### 코드 ↔ 시도 — 개수가 아니라 지명으로 맞춘다

처음에는 하위지역 **개수**만 보고 대응시켰다가 18개 중 7개를 틀렸다.
경북 데이터가 "충북"으로, 전남이 "경남"으로 나가고 있었다. 개수는 여러
시도가 우연히 같을 수 있어 근거가 되지 못한다.

각 코드마다 **그 시도에만 있는 지명**을 근거로 다시 맞췄다 (2026-08-05 실측).

| 코드 | 시도 | 근거 지명 | 코드 | 시도 | 근거 지명 |
|---|---|---|---|---|---|
| 01 | 서울 | 관악 | 11 | 경북 | 경산 |
| 02 | 경기 | 남양주 | 12 | 경남 | 거제 |
| 03 | 인천 | 미추홀 | 13 | 충북 | 괴산 |
| 04 | 부산 | 기장 | 14 | 충남 | 계룡 |
| 05 | 대구 | 달성 | 15 | 전북 | 고창 |
| 06 | 광주 | 광산 | 16 | 전남 | 고흥 |
| 07 | 대전 | 유성 | 17 | 제주 | 서귀포 |
| 09 | 울산 | 울주 | 18 | **광주·전남** | 광산 + 고흥 |

**`08`은 존재하지 않고 세종도 없다.** `18`은 광주(광산·남구·동구·북구·
서구)와 전남(강진·고흥·곡성·광양…)이 한 코드에 섞여 있어 시도 하나로
부를 수 없다. 새마을금고에서 본 것과 같은 형태다 — 화면의 지역 구분은
행정구역과 일대일이 아니다.

`tests/test_cu_collection.py::test_sido_codes_match_the_screen_subregions`가
이 대응을 못박는다.

**이 코드를 행정구역 공식 코드로 쓰지 않는다** (명세서 v3.1 §11).
`SIDO_NAMES`는 화면 표시용 이름표일 뿐이다.

### 3.4 기간은 진짜 요청 차원이다

FSB와 달리 `monTy`가 결과를 실제로 거른다. 응답 행의 `monTy`는 요청값과
항상 같다. 그래서 기간마다 요청을 나눈다.

실측(부산): 12개월 566건 / 24개월 453건 / 36개월 404건. **6개월은 0건**이다.

### 파서 설계 시 주의

- **금리가 `"3.40%"` 문자열이다.** 그대로 저장하면 크기 비교가 안 된다.
- **단리·복리 구분이 없다.** 표 헤더에 "이자계산방식"이 있는데 응답 필드에는
  대응하는 값이 없다. `interest_method = unknown`으로 둔다. 추측하지 않는다.
- **빈 값이 문자열 `"null"`로 온다** (`prefCondCode`). 진짜 값과 구분해야 한다.
- `rnum`·`listTotalCount`는 조회 결과에 따라 달라지므로 행 해시에서 뺀다.
  페이지를 다르게 넘겼다고 금리가 바뀐 것으로 잡히면 안 된다.

## 5. 지역의 의미 — 표기 규율

**조회 조건의 지역은 "그 지역에서 영업하는 조합"이라는 뜻이다.**
점포 주소가 아니다. 이 화면은 지번 주소를 주지 않는다.

그래서 파서는 `sido`만 조회 조건에서 채우고 `sigungu`·`address`는 **비운다.**
새마을금고처럼 주소에서 구·군을 뽑는 것이 불가능하다.

허용되는 표기:

```
부산에서 영업하는 신협의 조합 단위 공시금리
```

`부산 ○○구 신협 금리`가 아니다. 하위지역(`subSido`)으로 좁힐 수는 있지만
그것도 조회 필터이지 점포 소재지가 아니다.

금리 자체는 `cuIngno`(조합) 단위이므로 `rate_scope = INSTITUTION`이다 —
새마을금고와 같은 성질이다.

## 7. 미해소 항목

| 항목 | 상태 |
|---|---|
| 하위지역(`subSido`) 수집 | 하지 않는다. 조회 필터일 뿐 점포 소재지가 아니어서 구·군 비교에 쓸 수 없다 |
| 단리·복리 구분 | 응답에 없다. `unknown`으로 둔다 |
| 조합 점포 주소 | 이 화면에 없다. 별도 화면 정찰이 필요하다 |
| 6개월 0건의 의미 | 실제로 6개월 상품이 없는 것인지 조회 조건 문제인지 미확인 |

| 이용약관상 수집 허용 범위 | 확인하지 못했다. `policy_status: review` 유지 |
